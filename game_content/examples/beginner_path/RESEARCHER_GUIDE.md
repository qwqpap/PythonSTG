# N6.4 观察员说明

本文件帮助维护者把同一套材料交给五名真实新手。它不代替
`docs/N6_USABILITY_PROTOCOL.md`，也不能作为人工结果。

## 测试前

1. 为每名参与者准备同一提交、相互独立的干净项目副本。
2. 确认参与者以前没有使用过 PySTG。
3. 只提供本目录的 `README.md`，不要追加口头按钮说明。
4. 确认编辑器能用 `python tools/scene_editor.py --project .` 启动。
5. 为三项任务分别准备计时器和原始观察记录。

## 测试中

- 从参与者开始阅读每张任务卡时计时；
- 只观察和记录，不解释按钮、概念或正确操作顺序；
- 原样记录崩溃、错误提示、误操作、返回重做、求助和超时；
- 即使超时也允许继续，并记录最终用时；
- 参与者若写脚本，必须记录，本次结果不满足“无脚本”要求；
- 维护者发生一次口头带做，整份研究都不能通过。

## 每名参与者必须记录

- 匿名 ID；
- 是否有 PySTG 使用经验；
- Pattern、短道中、Boss 三项用时与完成状态；
- 是否写脚本；
- 求助次数；
- 具体失败点；
- 是否成功保存、重开、正式预览、撤销/重做和进入一次节点编辑。

## 测试后

把五名参与者的真实记录人工整理到 `reports/n6_usability.json`，再运行：

```powershell
python tools/verify_n6_usability.py reports/n6_usability.json
```

至少 4/5 人分别达到 10、30、60 分钟阈值才通过。报告必须由未参与实现的人复核原始记录。
不要生成虚构参与者、不要用自动化 fixture 冒充人工结果，也不要在报告通过前勾选 N6.4。
