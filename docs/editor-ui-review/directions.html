方案 C 做了什么：
  • 取消卡片式节点，改成"整行 + 底部分隔线"的代码行投影：同一屏能多看 5～6 个节点，信息密度最高。
  • 选中态用整行底色（蓝），类别只用左侧细色条标记，不再给每张卡片描边加投影。
  • 区块标题栏（内容导航 / 属性 / 时间线）用统一的深灰条，像 Blender / Unreal 的面板头。
  • 属性面板变密集表格：字段名固定 76px 右对齐，行高更小，一屏能放下更多参数。
  • 插入点只在鼠标经过时出现（样张里已省略常驻的插入行），程序流更接近"读代码"而不是"读表单"。
三个方向共同的看点（不随方案变化）：
  • 顶部把「编辑步骤 / 游戏画面 / 并排预览」收成导航分段控件，把「运行关卡 · F5」变成唯一主按钮，暂停/停止降为次要 —— 解决现在"6 个按钮长得一样、分不清切换还是执行"。
  • 节点之间只在缝隙出现插入线（A/B），不再每行常驻一个大号「＋ 添加」按钮冒充输入框。
  • 属性面板字段名右对齐、输入框等宽、去掉重复的「常量」标签 —— 现在这些会让面板看着乱。
  • 时间线从 90px 下限抬到 168px，刻度去掉重复的「帧」字，只在起点标注单位。
