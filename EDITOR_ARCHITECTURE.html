代码驱动关卡编辑器架构 ​

本文定义 PySTG 代码驱动关卡编辑器的稳定工程边界。产品行为见 EDITOR_PRODUCT_VISION.md，实施顺序和证据见 EDITOR_IMPLEMENTATION_TODO.md。

按所改行为查阅对应章节，整体架构或产品契约调整时完整阅读：

修改涉及章节
作者数据、DSL、源码保存、模板1–7
构建、生成代码、入口4、7–9
选择、Undo、Inspector、程序流、资产10–12，涉及持久化时加读 5
预览、进程、练习场、seek8、13–14
Timeline、静态预计与 Trace13、15
删除边界、测试与阶段验收16–18 和 TODO 对应 Gate

本文描述工程约束，不记录功能完成状态；当前实现和历史证据应分别核对。

入门界面仍依赖同一个 EditorSession：src/editor/onboarding.py 只展示欢迎页、当前内容 说明及已有动作按钮；src/editor/starter_content.py 只用普通 DSL 构造可编辑示例。 project_creation.py 通过标准源码写回器完成新建；window.py 负责选择、导航和单次 Undo 组合。示例和“添加一波弹幕”都不保存独立预设参数，不拥有另一套调度或预览。

2026-10-08：维护者已要求删除测试套件和验证脚本。第 17–18 节中的套件命令是历史约定， 不再要求重建或执行；当前修复采用即时功能检查，仍分别报告 Runtime、Native、Performance 和真人 Usability 的实际观察范围。

3. Headless 作者模型 ​

3.1 值 ​

作者值的闭集为：

  • None、bool、int、float、str；
  • 上述值组成的 list、tuple 和字符串键 dict；
  • Ref(id: str)；
  • Expr(source: str)；
  • res://... 字符串资源引用；
  • TemplateCall，其参数仍必须属于本闭集。

模型不执行 Expr。生成代码在对应 Runtime 函数上下文原样表达它，并把错误映射回节点。 Inspector 的列表、字典和参数默认值文本必须调用 headless parse_author_value；该解析器只 接受上述闭集及 Ref(...)/Expr(...)，不得由 Qt 使用 eval 或维护另一套值语法。

3.2 节点 ​

所有节点共享：

python
uid: str
kind: str
arguments: dict[str, AuthorValue]
children: dict[str, list[Node]]
source_span: SourceSpan | None
comments: NodeComments

公开 DSL 可以使用具体 dataclass 或带签名的构造函数，但模型必须能统一遍历、验证、复制和 生成。uid 在一个工程内唯一且稳定；移动节点不改变它。

3.3 逻辑单元 ​

每个文件恰有一个主逻辑单元赋值。逻辑单元固定保存：

python
kind: Project | Stage | Wave | Enemy | Boss | Spell | NonSpell | Task | Function
id: str
name: str
body: list[Node]
parameters: tuple[Parameter, ...]
metadata: dict[str, AuthorValue]
source_path: Path

Project 用引用声明 Stage 顺序和 start stage。其他单元通过 Ref 建立显式依赖。 解析器先收集工程内 ID，再验证引用和父子上下文。

program.py 公开 unit_accepts_statements(kind) -> bool。它只回答现有 Runtime 是否执行该 逻辑单元的 body：Project 与 Boss 为 false，Stage/Wave/Enemy/Spell/NonSpell/Task/Function 为 true。插入验证、原型工厂和 Qt 不得各自维护不同判断；Project 关卡顺序与 Boss phases 使用专用引用表面，而不是空节点树。

3.4 纯模型操作 ​

program.py 提供无 UI 副作用的操作：

  • unit_accepts_statements(kind)；
  • insert_node(parent, slot, index, node)；
  • delete_node(uid)；
  • move_node(uid, target, placement)；
  • wrap_node(uid, wrapper, slot)；
  • set_argument(uid, name, value)；
  • set_unit_field(unit_id, name, value)。

操作在副本上先验证，成功后一次提交；失败不部分修改。Qt QUndoCommand 只记录操作前后 必要状态并调用这些函数，不复制领域规则。

4. DSL 与 Runtime 镜像 ​

src.authoring.dsl 是作者唯一公开入口。节点构造函数的参数名、类型和默认值从现有 StageScript、Wave、EnemyScript、SpellCard 公共方法派生或显式镜像。

新增或修改 Runtime 公共方法时，必须在同一变更中更新 DSL 签名映射和 parity 测试。 Inspector 读取 Python 类型注解；不得维护单独的 JSON 参数描述器。

所有公开发射参数必须显式存在于 DSL 签名。包括弹型、颜色、tag、加速度/角加速度、阻尼、 时间缩放、反弹、自转、渲染角、缩放、寿命和曲线；作者入口不得使用不可发现的通用 kwargs。 单发与 batch codegen 必须得到同一运动语义。无法由 Runtime 实现的公开参数是构建错误，不能 静默 pop 或退化。

控制节点定义允许的 children slot：

节点children slot约束
Repeat / While / ForEach / Atbody语句节点
Ifbody, else_body语句节点
Parallelbranches每支为语句列表
SpawnTaskbody 或 task二选一
动作节点无不接受子节点

Break/Continue 只允许在循环内，Return 只允许在 Task/Function 或可返回模板体中。 RunWave、RunBoss 和 Spawn 类节点验证引用目标类型。

5. Python 源码协议 ​

5.1 允许的顶层结构 ​

  • 模块 docstring；
  • 普通 import 和 from ... import ...；
  • @template 函数定义；
  • 一个主逻辑单元的简单名称赋值；
  • 编辑器生成的必要注释和空行。

顶层 for、while、if、with、try、函数调用表达式、属性赋值、文件/网络/进程 操作以及多个主单元都进入只读诊断模式。

5.2 允许的表达式 ​

主单元和节点构造只解析：

  • 常量、列表、元组、字典；
  • 已知 DSL 构造函数；
  • Ref、Expr；
  • 由显式 import 解析到的模板调用；
  • 仅为负数所需的一元正负号。

不执行源码来加载工程。模板定义通过 AST 读取签名和返回结构；模板展开在受信任构建阶段 执行显式导入的模板代码。

5.3 注释与格式 ​

tokenize 把节点前连续注释、行尾注释和逻辑单元头注释关联到稳定 uid。写回器采用 确定性格式：UTF-8 无 BOM、LF、四空格、按源顺序保留 import、稳定关键字参数顺序。

不支持文件保存原始字节和诊断，不生成半结构模型。只读文件的任何保存 API 都必须明确 失败，不能落入普通 formatter。

5.4 外部修改状态机 ​

text
clean + empty undo + supported change -> reload
dirty or nonempty undo + disk change  -> conflict, freeze save
conflict + keep memory             -> explicit overwrite after confirmation
conflict + reload disk             -> replace model, clear undo
any + unsupported disk structure   -> readonly diagnostic, preserve bytes

即使文件已保存，非空 Undo 历史也需要用户明确选择后才能丢弃；只有 clean 且空栈时可自动重载。

新建文件在首次保存前只存在于内存；删除文件先进入可撤销墓碑。墓碑仍参与文件监视，磁盘 变化同样要求 keep/reload 决策。多文件保存保存前快照磁盘和文档元状态，任一写入失败时 两者一起回滚；失败后的再次保存不能漏掉仍在内存中的修改。单文件写入使用同目录临时文件、 flush/fsync（平台支持时）和 os.replace。

6. 模板解析与展开 ​

@template 函数有稳定的 module + qualname identity 和 inspect.Signature。项目模板与 外部模板都必须由作者文件显式 import。内置模板从 src.authoring.dsl 显式导出。

解析阶段创建未展开的 TemplateCall：调用 identity、原参数 AST、解析状态、调用 span、 定义 span。保存仍输出原调用。构建阶段：

  1. 按签名绑定并验证参数；
  2. 将 (template identity, bound args) 压入调用栈；
  3. 执行模板并验证返回节点；
  4. 为展开节点生成只用于构建和时间分析的派生 identity；
  5. 退出时弹栈。

同一 identity 在栈中再次出现即递归错误。任何异常诊断都包含调用节点 uid 和模板定义 位置。未知外部模板保留调用和参数但阻止构建；Timeline 显示动态未知聚合块。

7. 诊断 ​

统一诊断结构：

python
code: str
severity: error | warning | info
message: str
source_path: str
span: SourceSpan | None
unit_id: str | None
uid: str | None
related: tuple[RelatedLocation, ...]

稳定 code 至少覆盖：不支持语法、重复 ID/UID、未解析引用、引用类型错误、非法父子关系、 模板缺失/递归/异常、资源不存在、RawPython 语法错误、生成编译错误、入口注册错误和外部 文件冲突。

Problems 面板显示结构化诊断；Log 只显示有界进程文本。两者不能互相替代。

8. 确定性生成 ​

8.1 生成布局 ​

每个 Stage 拥有独立包；只把该 Stage 的传递引用闭包生成到对应分类目录。跨 Stage 共用 逻辑单元可以确定性重复生成，不产生运行时跨包隐式状态。文件名由经过验证的逻辑 ID 稳定映射，拒绝路径穿越、关键字和冲突。

根 entry.py 固定接口：

python
STAGES: tuple[type[StageScript], ...]
START_STAGE: type[StageScript]
STAGE_BY_ID: dict[str, type[StageScript]]

def get_stage(stage_id: str | None = None) -> type[StageScript]: ...

Stage 顺序等于 Project.stages；START_STAGE 等于 Project.start_stage。重复或缺失 Stage 阻止构建。

8.2 代码生成 ​

生成类直接继承现有 Runtime 类，async def run() 按节点递归输出现有 API 调用。 控制节点映射为普通 Python 控制流。RawPython 只插入当前生成函数体。

高密度发射保持现有批量 API；禁止生成每颗子弹的场景节点、闭包或 Python per-frame callback。Trace 仅在作者节点边界调用轻量 emitter，并由运行时批量刷新。

2026-10-11 Runtime 维护边界：正式帧任务实现归 src/game/tasks.py；生成 _support 只导入并调用它，不再携带自己的任务调度循环。Stage/Wave/Enemy/Spell 持有任务组， 按自身帧更新推进；结束/取消负责关闭主协程及子任务。受击属于稀疏任务，不逐弹建立任务。 死亡后需要继续的反应归仍存活的 StageContext，连同引用 Task 的并行子任务、局部时钟和 Trace 一起接到该帧时钟；仍可从死去的敌人读取发射位置，不依赖其继续 update。 Task/Function 的引用链在 headless 模型和模板展开后验证实际调用者能力；不得用 Task 绕过 Stage/Wave 的动作或位置要求。取消时先关闭各任务作用域，再由 StageManager 收集 finally 产生的 Trace；清理 Context 不得提前丢弃这些结束记录。

2026-10-13 粒子补充仍归同一 Runtime：src/game/particle.py 是独立有限 SoA 池， 共享 ParticleEffect 视觉帧表；Numba 更新/紧凑存活索引/实例打包，不导入 Qt、renderer 或 actor。寿命/动画/速度不靠每粒子 Task，清弹、碰撞和擦弹不扫描粒子。 StageManager 持有池，StageContext 提供 emit/read/transform/count/clear，作用域 dispose 清理；read 返回脱离池的只读快照，transform 按出生代和原始行对齐批量写回。 特殊投影/数值规则由一个普通 Task 的整批 NumPy/Numba 公式表达，不新增粒子调度器。 粒子速度/加速度分别为单位/秒、单位/秒²，明确区别于历史敌弹加速度约定。 src/render/particle_renderer.py 只拥有自己的 GL 缓冲/程序，纹理由现有资源管理器持有； Renderer.cleanup 释放粒子绘制资源。back/front 层分别在敌人之后/道具之前和激光之后/ 判定点之前；同层保持出生顺序，按相邻纹理/混合段实例绘制，保留半透明重叠含义。 正式循环和独立预览先更新已有粒子，再推进脚本；effects mask 停模拟，不停绘制。 continue 清空装饰；候选预览独立持有新池，失败不污染旧池/RNG，成功才替换。 不新增纯 GUI 节点或 ANM VM；原作贴图/动画、附属 actor 动画和深度表现分别待移植。

上述高级控制不自动成为 GUI 节点，也不改变 restricted Python 作者协议。已有 MoveTo 的 easing 经 DSL/生成器映射到共用移动实现，其余普通内容规则可通过既有 RawPython 入口使用；具体覆盖与未移植的原作策略见 TH06_API_COVERAGE.md。

游戏逻辑统一按 60 Hz 仿真步执行；真实帧耗时只影响呈现/帧率统计。本轮保持原有 “子弹池更新 → 关卡任务 → 碰撞”的顺序，控制流程新弹从下一仿真步运动/碰撞。 更新中二级出生也从下一步更新/碰撞，不能取决于空闲槽位编号。清场与自然终结原因分别处理； clear_all 是整个弹幕作用域的取消，不再生，并取消反应注册、未出生队列、阶段定义和冷却规则。

渲染继续复用现有实例缓冲、ModernGL 和混合顺序。加速优先减少 Python 热循环、临时数组和 重复复制/提交；JIT 编译时间与稳态帧耗时分别测量。Rust 不进入本轮依赖；以后只在测量 证明必要时替换整批数组数值内核，不把关卡/API/编辑器迁入 Rust，也不跨语言逐弹调用。

图集上传方向与 SpriteRegistry UV 必须一致：main 和独立符卡工具上传使用 flip_y=True， 注册也显式传 flip_y=True。注册默认 False 保留未翻转调用；此接线不改变 shader、排序、 混合或资源格式。JIT、CPU 提交/呈现、实际 GPU query 分别测量，不用池层耗时代替整帧。

text

8.4 事务构建 ​

text
validate memory model
  -> generate sibling temp directory
  -> write Python/manifest/source_map
  -> child process compileall
  -> child process import entry
  -> validate stage registry and references
  -> return prepared build
  -> preview owner stops old process
  -> atomic directory replacement
  -> preview owner starts new process

PackageBuilder.prepare() 在全新的 headless Python 构建进程中展开模板、生成代码、编译、 导入并验证注册结果；CLI 有 60 秒超时。GUI 由 PreviewOwner 异步启动同一构建入口，允许 停止，不在 Qt 信号处理期间同步执行模板。构建进程每次重新读源码，不复用旧模板模块或字节码。 独立构建通过后才停止旧预览，并调用 begin_publish() 保留旧正式目录备份。新游戏已进入 运行状态、且 Windows 子窗口实际嵌入后才 commit() 删除备份；发布或启动失败先回滚生成包， 再恢复旧启动参数、目标和构建标识，重新启动旧构建。验证失败时旧预览无需停止。CLI 没有 游戏握手步骤，publish() 直接完成发布。文件占用或恢复失败必须报告，不能声称旧预览仍在运行。

生成哈希只覆盖规范化作者语义、模板版本/源码和生成器版本，不包含绝对路径或时间戳。 同一输入连续构建必须逐字节一致。

11. Qt 布局与交互 ​

window.py 组装步骤主导工作区，不实现领域验证。默认中央只展示编辑步骤；引用可直接打开， 顶部返回/路径恢复原单元、选择与滚动位置。导航优先显示当前关卡的出场/引用关系，全部内容 是管理入口。Inspector 是右侧辅助栏，基础参数优先；帮助、源码、节点库和预览按需展开。 宽窗口可显式选择并排预览，窄窗口在步骤/画面之间切换；Run 不永久挤压步骤。 Timeline 保留底部概要，可展开详细阅读，不建立第二作者文档。 左侧“源码”页按中文内容名称列出作者文件，完整相对路径放在提示中；单击打开对应只读 作者源码，“编辑步骤”可返回编排。源码页不是新手添加内容的入口。

视觉是单一 token 源，不散落在各控件里：src/editor/theme.py 定义颜色、间距、字号、 圆角与关键几何值，并由这些值生成唯一一份 QSS；app.py 用 app.setStyleSheet() 做应用级 挂载，使对话框、菜单、工具提示、下拉列表等顶层弹窗与主窗口共用同一主题（子控件级样式表 无法覆盖顶层弹窗，会出现白色弹窗）。面板、按钮、树、滚动条、时间线、程序流的颜色都从 PALETTE 取值；自绘控件（program_tree.py、timeline.py）读同一个对象，因此换肤不改 绘制逻辑。样式表只影响外观，不得在其中携带领域判断或改动信号接线。

当前视觉方向（维护者选定）：中性灰的紧凑工具风。程序流是"代码行"而不是卡片：整行底色 表达选中/悬停，左侧类别色条表达节点类别，底部分隔线表达层级，不再描边加投影；节点之间 默认只画安静的插入引导线，鼠标经过或正在拖放时才显示落点标记与提示，不逐缝常驻大按钮。 面板头（内容导航/属性/时间线）使用同一种深灰标题条；时间线保留底部概要但不被压成一条缝。

步骤之间与空容器的 + 是主要添加入口，弹出 node_palette.py 的同后端搜索，支持上下、 Enter 和 Esc；完整节点库可从视图菜单打开，不默认占据半个侧栏。节点库只保存中文标签和类别；构造函数参数、父子规则与引用 候选类型分别由 headless node_from_palette、validate_insert 和 reference_kinds_for_node 推导。缺少引用候选时节点库显示明确的新建对应逻辑单元入口。 新节点使用瞬态 MIME application/x-pystg-node-prototype，逻辑单元使用 application/x-pystg-unit-ref；两者都只携带 identity，不保存作者数据。

中央程序流（program_tree.py 的 ProgramFlow）是自定义绘制的纵向块式投影：每个节点一张 缩进卡片；Repeat/If/At/SpawnTask 直接展示嵌套区域；空容器显示“拖到这里添加内容”； If 显示“条件成立/否则”；Parallel 分支在宽视口并排、窄视口纵向堆叠；支持折叠、边缘 自动滚动、悬停展开和 Esc 取消拖动。Project 与 Boss 改为各自的关卡顺序/phases 表面。 普通单体容器不再添加无意义的“内容”标题；非空容器复用末尾插入线，不再绘制重复尾槽。 只有真正空的根或分支保留添加落点，If/Parallel 的分支标题保留语义。引用卡片优先 显示中文内容名称，拖动手柄使用点阵，套进容器的入口标为「套一层」。

程序节点拖拽先计算唯一 DropPlacement：BEFORE、AFTER、CHILD、WRAP。Before/After 用节点间插入线，Child 用可见容器内容区，Wrap 用可见手柄或 Alt 拖放；不得再用悬浮四区 放大面板或全局插入模式。已有节点只从拖动手柄移动。释放时生成恰一个 QUndoCommand； Inspector 和资源拖拽同理。放置成功后选中新节点、闪烁高亮，并把 Inspector 滚动到建议 首先修改的字段。 Inspector 从 DSL 注解生成 Literal、Ref、常量/Expr、资源、列表/字典控件；Task/Function 参数使用名称/类型/默认值三列表格，提交仍进入同一个 Undo 栈。它以中文展示位置、发射形状、 运动、外观、声音和生命周期，能从现有 alias/atlas 查询弹型缩略图和参数几何示意，但不能 复制 DSL 默认值、父子规则或 Runtime 语义。模板原型从已解析签名取得默认参数，保存时保持 模板调用而不展开。显式外部模板的节点库签名通过模块源码静态读取，编辑/刷新节点库不得 import 或执行外部模块；可信代码只在构建展开阶段执行。 只有明确的 res:// 语义字段显示资源拖入与文件选择；逻辑单元显示名等普通字符串使用 普通文本框，不伪装为资源字段。 浮点参数使用精确文本输入，不经有限小数位的 spinbox 截断；提交、保存和重新解析保持原值。 引用选择显示内容名称，重复名称附 ID；保存仍是英文 ID，允许直接输入 ID。 属性中的打开按钮按当前文本解析目标，与提交使用相同的名称/ID 对应，不读取过期的下拉选中项。

作者源码和生成源码视图使用只读文本控件。受支持文件也不提供任意文本编辑器；外部编辑 由文件监视器加载。首版所有作者可见 UI 字符串为简体中文。

12. 资产视图 ​

全局资产从 ProjectContext 根扫描稳定支持扩展名，不跟随当前工作目录。扫描排除隐藏 文件/目录、已知构建/依赖目录、顶层 docs/ 和开发配置文件；普通游戏 JSON 与自定义 资源目录保留。资源页支持按名称/位置搜索和图片、音频、字体、数据分类；列表显示短文件名， 完整相对路径与原始 res:// 放在提示中，拖拽继续携带原始 URI。Stage 资产集合算法：

  1. 从当前 Stage 开始遍历 Ref；
  2. 防循环并按逻辑单元 ID 稳定排序；
  3. 收集参数值中显式 res://；
  4. 验证路径仍位于项目根；
  5. 不解析 Expr 或 RawPython 内字符串。

资源拖入字段前根据构造函数注解验证类型。拖入插入线时只显示该资源类型对应的明确动作 列表；用户选择后才创建节点命令。

13. 预览所有权与协议 ​

PreviewOwner 是唯一 QProcess 所有者，状态为：

text
stopped -> building -> starting -> running <-> paused
running/paused + edit -> same transport + stale flag
any -> stopping -> stopped
any process failure -> error -> stopped

Run 在临时构建完成全部验证前不停止旧预览。验证成功后，owner 发送 stop、等待有界超时、 必要时终止旧进程；确认退出后调用 builder 原子发布，再启动新进程。发布或启动失败时 builder 回滚，owner 重新启动旧构建；新进程握手及嵌入完成前不能确认构建成功。编辑只设置 源码已改标记，不改变 running/paused 播放状态。

控制消息只允许：pause、resume、restart、seek、stop。事件只允许：ready、 state、frame、trace、error、stopped。消息带协议版本和本次 run identity；过期 进程事件丢弃。trace 可携带节点边界和固定采样的 emitted/live/laser 聚合指标，但不得 携带逐子弹回调或无界事件流。stdout/stderr 和 Trace 队列都有硬上限。

Windows PreviewHost 只负责发现该 QProcess 创建的 GLFW 顶层窗口、验证 PID、保存原 window style/parent、调用 Win32 SetParent 和尺寸/焦点同步，并在退出时恢复/释放。 它不拥有进程、不创建备用 renderer，也不把截图当作嵌入成功。

14. 练习场与 seek ​

Project/Stage 直接使用生成入口。Wave、Enemy、Spell 由一个标准生成练习 Stage 包装， 仍通过 StageManager 和正式游戏循环运行。

每次 run 记录 seed、目标和构建 hash。seek 必须以相同 identity 重启，从帧 0 快进到目标 帧；快进期间关闭音频和中间帧呈现，但不跳过游戏逻辑。动态外部输入使 seek 明确标记为 不可复现。

普通手写符卡工具 tools/preview_spell.py 使用 src/devtools/spell_preview.py 包装同一 Boss/Context/EventBus/Pool，而不是另一套玩法 Runtime。每步先推进已有子弹/激光/道具/粒子， 再推进 Context 任务、敌人和符卡；新弹/转换敌人次帧才更新。重启先准备独立候选池与 RNG，失败保留旧实例，成功才替换全部池；外部 renderer 必须读取当前池，不缓存最初引用。 结束时只等待明确的 end_reaction 及其 awaited 子任务，不等待无关无限后台任务；关闭和 异常取消作用域并执行 finally。该工具只显示转换敌人的位置标记，没有完整玩家射击、 受伤、Bomb 或整关结算。文件监视只服务该手写开发工具，不改变 GUI 显式 Run/stale 契约。 其 GLFW 呈现也不能冒充 PySide6 嵌入或真人编辑器验收。

15. Timeline 分析 ​

Headless Timeline analyzer 输出 TimelineInterval，不序列化回作者文件：

python
uid: str
parent_uid: str | None
start: int | Unknown                 # 静态预计
end: int | Unknown                   # 静态预计
observed_start: int | None           # 同一 run identity 的 Trace
observed_end: int | None
lane: str
kind: static | branch | parallel | spawned | template | dynamic
display: span | milestone | aggregate | unknown
editable: none | wait | duration | at
children: tuple[TimelineInterval, ...]

投影还包含章节、lane 层级和可选的有界指标桶。静态规则：顺序累加、Wait 推进、常量 Repeat 计算聚合时间、Parallel 分泳道且 awaited 取最长、SpawnTask 不阻塞、If 显示分支范围。 父容器显示为章节背景或括号，叶节点显示真实区间；零时长动作用 milestone；动态循环、 RawPython、动态 Expr 和未知模板传播 Unknown，不猜数值，后续节点仍保留源顺序。 Qt 时间线为每个源步骤安排独立一行；固定左列显示中文名称与层级，右侧区间按真实帧数 比例绘制，不用最小块宽伪造时长，也不将文字挤入短区间。父容器使用章节括号；未知时间 放在明确的非时间区域。横向滚动保持名称可见，纵向滚动保持标尺/左列标题可见；部分可见 行在可见区域足以容纳完整字时仍显示名称，不绘制半截文字；选中项定位为固定标尺预留空间。首次显示/切换内容适应视口，同内容 编辑和 Trace 更新保留手动缩放。绘制布局不修改 headless 时间推导或源码语义。

Trace overlay 以 run identity 和 uid 填入 observed_start/observed_end/branch，而非覆盖 静态 start/end。它不修改静态模型、源文件、dirty 或 Undo。点击区间选择节点，点击节点选择 对应区间。

反向编辑必须先证明目标参数是字面量：Wait.frames、任意声明为 duration 的字面量参数、 At.frame。除此之外 Timeline 不产生命令。 时长右缘的命中优先于相邻区块正文，命中容差不改变实际绘制区间；正文拖动不修改时长。 循环范围是临时查看状态：切换投影内容重置默认范围，同内容编辑和 Trace 更新保留手填值； 启用循环绑定内容与运行 identity，不兼容目标不可 seek，也不把循环范围保存为作者数据。

每阶段按 TODO 运行 focused gate。局部修改先验证受影响行为，通过后无需无故重复扩大测试。 文档措辞、链接和导航修改只检查链接、入口与 npm run docs:build，不据此更新技术 Gate。 阶段/路线完成仍执行 TODO 第 9 节全部最终门禁；维护者已删除测试套件与原生验证脚本，因此 第 17 节列出的测试分类、以及历史 Gate 中的 pytest/verifier 命令只作行为核对清单，不再是 当前工作树的执行入口。当前快速合并检查基线：
